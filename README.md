# AI Visibility Dashboard

A compact Next.js dashboard for exploring AsterVision's visibility across AI platforms, topics, and user questions. The application uses the supplied JSON files as its data source, ECharts for visualizations, and a server-side LLM integration for generated analysis when configured.

## Features

- Dashboard metrics for Visibility Score, mentions, recommendations, and citations.
- ECharts trend and platform performance visualizations, plus topic performance cards.
- Searchable and filterable question analysis (keyword, platform, topic, and brand status).
- Question detail drawer with answer excerpt, mention/recommendation status, sentiment, products, and citation links.
- AI Insight action for question-level analysis. It calls an OpenAI-compatible Chat Completions API when credentials are configured, and returns a Mock AI analysis when no API key is present.
- Loading, request error, and no-results states.

## Requirements

- Node.js 20 or newer
- npm

## Run locally

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

For a production build:

```bash
npm run build
npm start
```

## LLM configuration

Copy `.env.example` to `.env.local` and set the provider values:

```env
OPENAI_API_KEY=your-secret-api-key
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-4o-mini
```

`OPENAI_BASE_URL` should be the provider's API base URL (without the `/chat/completions` suffix). The server route calls `${OPENAI_BASE_URL}/chat/completions`. The key is read only by the server and must not be added to client-side code. Restart the development server after changing environment variables.

If `OPENAI_API_KEY` is empty or unset, `/api/insights` returns a deterministic Mock AI result. Provider/network errors are returned to the UI so they can be corrected; they do not silently fall back to Mock output.

## API routes

| Method | Route | Description |
| --- | --- | --- |
| `GET` | `/api/dashboard` | Returns dashboard summary, platform statistics, daily trend, and topic statistics. |
| `GET` | `/api/questions` | Returns question records. Supports `search`, `platform`, `topic`, and `status` query parameters. Use `all` (or omit a parameter) for no filter. Status values: `recommended`, `mentioned`, `missed`. |
| `POST` | `/api/insights` | Generates an insight. Send `{ "questionId": 1 }` to analyze one question; send `{}` for dashboard-level analysis. Returns `insight`, `provider`, and `model`. |

Example request:

```http
POST /api/insights
Content-Type: application/json

{"questionId": 1}
```

## Data flow

```text
Browser (app/page.tsx)
  ├── GET /api/dashboard ── dashboard_summary.json
  ├── GET /api/questions ── questions.json
  └── POST /api/insights ── LLM provider or Mock AI
```

The API handlers live in `app/api/*/route.ts`. Shared TypeScript types are in `lib/types.ts`, and `lib/data.ts` imports the supplied JSON datasets. ECharts components are in `components/Charts.tsx`.

## Project structure

```text
app/
  api/                 Next.js API route handlers
  globals.css          Global and responsive styles
  layout.tsx           Root layout and metadata
  page.tsx             Dashboard page and UI interactions
components/
  Charts.tsx           ECharts trend and platform charts
lib/
  data.ts              JSON data imports
  types.ts             Shared TypeScript data types
dashboard_summary.json Dashboard metrics, platforms, trends, and topics
questions.json         Question-level records and citations
```

`.next/` is generated by Next.js during development/build and should not be edited by hand.
